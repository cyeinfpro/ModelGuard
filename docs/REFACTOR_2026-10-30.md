# ModelGuard 0.3.0：全链路体验重构

日期：2026-10-30（北京时间）
基线：0.2.1 / 6f3e690
范围：插件界面、配置与宿主桥接、账号发现、任务调度与状态、API 凭据桥接、验证与打包。
本文记录已完成的代码重构、设计约束、验证结果与交付边界。源码已经写回项目；正式签发与部署不在本轮执行范围。

## 1. 这次重构解决什么

ModelGuard 的主要任务是让管理者及时看清账号的模型指纹检测结果，并在明确开启自动处理时管理本插件持有的暂停记录。界面需要持续回答三个问题：

1. 我现在需要做什么？
2. 我刚才的操作是否真正生效？
3. 接下来由系统处理什么，什么时候需要我处理？

首次接入按“连接管理端 → 选择账号 → 确认策略并开始”组织；已有配置进入巡检工作台。连接、账号选择、策略调整放在有顺序的编辑区域，后台状态始终对应已生效配置。用户编辑中的内容不应被轮询覆盖。

指纹库给出参考类的统计相似度。产品不能把“采样失败”“网络慢”“没有完整响应”翻译为“模型不符”，也不能把指纹结果承诺为身份认证或能力证明。

## 2. 基线中确认的问题

| 层面 | 已确认的问题 | 对用户的影响 |
| --- | --- | --- |
| 首次接入 | 账号列表先出现，管理地址和密钥藏在二级折叠中 | 用户不知道为何空白、下一步该填哪里 |
| 配置与诊断 | 表单草稿、已保存配置和运行时状态混在同一页面 | 容易误以为刚修改的连接已经被测试 |
| 宿主契约 | UI 的 config.test 没有配置参数，测试的是已保存配置 | 不能仅给 postMessage 增加 config 字段就宣称支持草稿预检 |
| 手动命令 | 保存 nonce 后再测试，与普通诊断共用 TestConfig | 必须保证诊断不会误消费命令，失败不会变成“已开始” |
| 任务状态 | 采样、整轮完成、不可用、暂停、恢复是不同事实 | 单一绿色/红色标签无法解释当前调度状态 |
| 自动化策略 | 自动暂停、自动恢复、定时检测存在组合关系 | 用户需要看到当前组合的实际行为 |
| 凭据桥接 | urllib 默认跟随跳转；工作线程之外的待处理队列无界 | 需要禁止凭据跨跳转发送，并限制排队资源 |
| 桥接启动 | 启动时直接 unlink 已有 socket | 第二次启动可能覆盖正在运行的服务入口 |
| 构建交付 | 多处硬编码 0.2.1 包名，旧包测试可能与当前源码混淆 | 新代码必须对应新版本的运行文件和安装包 |

## 3. 宿主真实契约

核对来源为官方 Sub2API v0.2.19：

- [UI Bridge v1](https://github.com/Wei-Shaw/sub2api/blob/v0.2.19/backend/pkg/pluginapi/docs/ui-bridge.md)
- [插件开发约定](https://github.com/Wei-Shaw/sub2api/blob/v0.2.19/backend/pkg/pluginapi/docs/development.md)

必须遵守以下边界：

| 消息 | 能做什么 | 本次设计要求 |
| --- | --- | --- |
| config.load | 读取已保存配置 | 初始化与显式放弃修改使用 |
| config.save | 验证、应用并保存配置 | 只提交本次操作承诺保存的内容 |
| config.test | 测试已保存配置 | 连接步骤先保存连接，再加载与检查 |
| plugin.status | 读取运行时 Health 快照 | 轮询使用此通道，不主动触发检测 |
| ui.resize | 通知 iframe 高度 | 内容变化时合并通知，避免反复抖动 |
| ui.notify | 宿主提示 | 非必要不依赖外层弹窗完成核心流程 |

沙箱 iframe 不能访问宿主 Cookie、父页面 DOM 或宿主的浏览器存储，不能绕过宿主直接调用管理 API。接收消息同时校验来源窗口、source、Bridge Token 和等待中的 request_id，并清理超时与卸载时的待处理请求。

**连接检查成功只证明当前管理密钥能读取返回的账号范围。它不证明所有写权限、所有上游模型和可选桥接均已验证。** 尤其不能为了检测 accounts.status 权限而对真实账号执行一次暂停/恢复。

## 4. 用户操作主线

### 4.1 第一次使用

第一步展示管理地址和管理员访问密钥，说明所需范围。连接操作的文案必须包含真实的保存行为。保存后加载账号；失败留在当前步骤，保留输入内容，并给出可操作原因。

第二步按密钥授权范围显示账号。推荐请求模型与预期参考类由现有账号建议值提供。账号不可见、类型不支持、API 桥接未就绪与外部暂停需要区分，不能都折成“失败”。

第三步确认账号数量、定时策略、自动暂停/恢复行为和并发。主按钮开始一轮检测时，要区分“配置已经保存”和“后台已经接受检测”，不能收到保存回执就显示已开始。

### 4.2 日常查看

打开后先看到已生效的巡检范围和当前任务。用户能直接确认：

- 正在运行、正在排队、处于启动保护期，还是已关闭定时检测。
- 当前完整采样进度，以及重试中的具体样本。
- 哪些账号通过、哪些参考结果不符、哪些没有形成有效结果。
- 当前能否被 Sub2API 调度；如果暂停，由谁暂停。
- 下一次检测/恢复确认时间或等待条件。

配置编辑与巡检观察分开管理状态。编辑草稿可以保留，但工作台不能把草稿目标当作已经开始巡检的账号。

### 4.3 修改配置

普通保存只保存；立即检测可保存本次明确提交的配置并发起一轮检测。两者需要清楚区分。

当后台批次不允许热切换配置时，页面保留输入并解释等待原因；不丢草稿，不假装应用成功。旧状态请求不能晚到后覆盖新配置显示。连接字段变化后，旧连接验证结果应失效。

实现中，纯连接诊断会读取最新已保存配置，清除残留的手动请求标识，再调用 config.test，并严格验证连接类型回执。没有收到本次手动请求 ID 对应的接受回执时，不显示已开始检测。已保存目标为空而草稿已勾选账号时，首次开始不会被旧的 targets_required 状态卡住。

### 4.4 失败与恢复

| 情况 | 正确含义 | 下一步 |
| --- | --- | --- |
| 页面与宿主断开 | 最新状态未知 | 保留最后一次同步时间，恢复后重连 |
| 管理接口不可达 | 账号管理信息暂不可用 | 检查连接或等待后台重试 |
| 密钥失效或缺范围 | 当前操作未获管理端授权 | 修改密钥或账号授权范围 |
| 流中断、超时、有效样本不足 | 没有可靠指纹结论 | 对失败样本有限重试，保留调度状态 |
| 参考结果不符、仅观察 | 提示人工判断 | 显示结果与下一轮计划，不冒充已暂停 |
| 本插件确认暂停 | 暂停新调度 | 按隔离复测与恢复规则继续 |
| 连续有效复测通过 | 满足恢复的证据条件 | 恢复前继续校验状态与归属 |
| 外部暂停 | 本插件不拥有该暂停 | 只允许按既有规则观察，不自动恢复 |
| 外部修改过暂停记录 | 原归属证据已经失效 | 明确显示保留现状与处理原因 |
| 请求预算不足 | 无法保证完整一轮 | 展示剩余量及实际重置时间 |
| 状态持久化失败 | 操作证据无法可靠保存 | 明确停止危险状态变更，保留错误 |

## 5. 视觉与交互原则

页面使用一套间距、排版、边框、焦点和语义颜色。纯白背景与清晰文字作为主体，强调色集中在主操作和必要的状态上。颜色之外还必须有文字说明，避免依赖红绿辨认。

桌面兼顾快速扫读和账号密度；手机按实际阅读顺序组织账号与操作。必要的模型选项、诊断和历史记录按需展开，不用大弹窗承载整套设置。

交互细节包括：

- 提交期间按钮提供动作反馈；重复点击不会重复发起后台任务。
- 错误信息与对应操作靠近，成功消息与实时错误分开。
- 筛选与搜索只影响展示；批量选择准确限定在当前可操作范围。
- 无结果、未连接、没有授权账号、未选择账号分别提供下一步。
- 表单字段有真实 label；焦点可见；键盘可以完成主要步骤。
- 动效用于表达状态变化，尊重 prefers-reduced-motion。
- 账号名称和错误内容作为文本插入，避免 HTML 注入。
- 管理密钥不进入状态投影和日志；上游凭据与原始回答不进入巡检记录。

## 6. 核心运行规则

并发限制对手动与定时批次共同生效。每个账号先获得完整一轮的预算，再开始采样，失败重试不能侵占其他已安排账号的基本采样预算。

保存后的启动保护期继续保留，用于兼容宿主临时测试进程；它不是页面卡住。手动检测可明确排队，不能在启动或 Health 读取时回放历史命令。

暂停/恢复的持久化记录支撑重启后的保守校验。网络回执不确定时保留待核对记录，不凭空取得自动恢复所有权。任何恢复仍须检查最新账号状态、暂停归属及修改版本。

已经落地的调度修复包括：

- 暂停/恢复前的管理端读取和写入不再占用全局状态锁；同账号仍由 inFlight 保证串行，慢账号不会卡住其他账号。
- 配置切换通过 TrySuspend 在同一门控内完成空闲检查与暂停调度，避免检查后又启动新批次。
- 手动请求先持久化为 queued 才返回接受回执；保存失败不消耗请求 ID，重启后标记 interrupted 而不自动重放。
- 批次区分完成、部分错误和中断；取消中的账号不虚增完成数，正常统计摘要不进入 last_error。
- 普通进度刷新和另一个账号的成功不会抹去尚未解决的错误；持久化故障独立显示。
- 自动恢复与新增自动暂停分别控制；关闭自动暂停不会偷偷关闭已有隔离的自动恢复策略。
- 取消监测的自有暂停记录继续可见，但不承诺自动复测；重新勾选并保存后才能继续。
- 运行进程启动和配置回滚均失败时，Health 与页面返回真实 runtime_error，禁止发起采样并保留配置修复入口。

**宿主调度接口没有原子的条件更新。** 插件可以缩小竞态窗口并避免盲目恢复，但不能声称消除了外部控制器同时写入的所有竞态。部署时不应让多个自动控制器同时管理同一个账号。

## 7. API 桥接改造

桥接继续作为可选的本机 Unix Socket 服务，不增加 TCP 监听、不修改 Sub2API 数据库，不自动安装系统服务。OAuth 继续走宿主身份接口。

本次将桥接整理为可测试的配置、授权读取、数据库读取、请求处理和服务生命周期模块：

- 管理 URL 限定本机，禁止 HTTP 跳转，并不继承环境 HTTP 代理。
- 数据库读取前后验证管理员密钥对该账号的权限；范围、类型和状态变化时不返回凭据。
- 只对严格校验的正整数账号 ID 执行 SELECT。
- 空令牌、异常响应和不支持账号不会被当成成功。
- 最多 8 个工作线程、16 个额外等待连接，超额连接关闭后由调用方按失败处理。
- 启动加进程锁；不覆盖正在服务的 socket，不删除普通文件或链接。
- 退出仅清理自己拥有的 socket。
- 错误响应不返回原始异常、SQL、上游地址或凭据，并加 no-store。
- 自动化测试全部使用临时目录、假账号和本地测试服务，不读取生产密钥或数据库。

### 尚未完成的验收边界

浏览器视觉验收受当前执行环境限制：本地缺少浏览器且官方下载不可达；云浏览器不允许加载本地 file URL。未绕过浏览器策略，因此不把 DOM 行为测试当作已完成像素级或真机验收。
