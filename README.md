# ModelGuard · 模型哨兵

Sub2API 的账号模型指纹巡检插件。按“连接管理端 → 选择账号 → 确认策略并开始”完成接入，之后在同一工作台查看队列、采样、结果、暂停归属和下一步。

当前工作版本：**0.4.1**。本次优化与验收范围见 [0.4.0 优化落地记录](docs/IMPLEMENTATION_2026-11-05.md)，此前重构见 [全链路重构记录](docs/REFACTOR_2026-10-30.md)。

**指纹表示参考库内的统计相似度，不是模型身份认证或智力证明。** 超时、拒答、流中断和不完整样本不算指纹不符。

## 开始使用

### 1. 安装并启用插件

从 [Releases](https://github.com/cyeinfpro/ModelGuard/releases) 下载 `.s2plugin` 和 `SHA256SUMS`。默认发布无需外部签名私钥，下载后按 SHA256SUMS 核对归档，再使用宿主管理页上传更新。

首次使用默认安装包时，在 Sub2API 实际配置中启用自建无签名插件，并正常重启宿主加载配置：

```yaml
plugins:
  allow_unsigned: true
```

这是宿主级选项，对该宿主的插件安装均生效；上传仍需管理员授权。宿主继续检查清单、文件 SHA-256、路径安全和兼容性，但无签名包不提供发布者身份证明。保持此设置可支持后续更新和从数据库原包恢复。已有 trusted_publishers 可以保留，带签名的包仍须通过原有验签。

更新同一个插件时，先停用，再上传新版并恢复原启用状态及灰度比例；不要卸载或删除插件状态目录。

启用插件后打开配置页。插件进程是否启用，与插件内“定时检测”是否开启，是两个不同状态；关闭定时检测仍可以手动检测。

宿主契约按官方 Sub2API 0.2.19 对齐，兼容声明为 `>=0.2.19 <0.3.0`。插件参与 `openai.oauth.outbound_transport.v1` 绑定，部署时检查现有传输插件。默认状态目录为 `/app/data/sub2api-account-guard`。

为兼容已有安装，内部插件 ID 仍为 `local.sub2api.account-guard`，状态目录保持兼容。

### 2. 连接管理端

在接入第一步填写本站管理地址和管理员访问密钥，执行“保存连接并加载账号”。

管理地址使用站点根地址，例如 `http://127.0.0.1:8080`。非本机地址必须使用 HTTPS。密钥授权范围需要覆盖准备巡检的账号：

- 读取账号需要 `accounts.read`。
- 自动暂停与自动恢复还需要 `accounts.status`。

宿主 UI Bridge v1 的 `config.test` 只测试已保存配置，所以连接操作先保存，再检查与加载。连接成功表示能读取相应账号列表，不表示已经验证所有上游模型或调度写权限。插件不会通过暂停真实账号来测试写权限。

### 3. 选择账号与策略

手选模式下，勾选需要巡检的账号。常规使用采用账号推荐模型；需要指定渠道模型名或参考类时，再展开模型设置。

也可展开“按分组持续同步账号”，填写最多 100 个不重复正整数分组 ID（逗号或空格分隔）。`group_ids` 留空为手选模式；非空时以定时读取的当前分组成员为准，删除或移出分组后不恢复，不把动态成员回写为手选配置。可同时设置 `group_model` / `group_expected` 作为新成员模板；均留空时新成员先等待配置，不擅自猜测模型。宿主账号接口必须返回明确的 `group_ids` 数组；字段缺失/null 或同步失败时保留记录并停止按旧成员关系恢复。当前为手填分组 ID，不声称已读取宿主分组名称列表。

“请求模型”是发送给上游的名称；“预期指纹”是检测时对照的参考类。API 渠道可以对模型名做映射，这两个名称不一定相同。

确认定时检测、并发和自动处理行为后开始。工作台区分配置保存回执和后台检测接收状态，不把“已保存”当成“已检测”。

## 日常操作

| 想做什么 | 操作与结果 |
| --- | --- |
| 看当前情况 | 查看工作台中的账号、调度状态、采样阶段和下一步 |
| 手动检测一次 | 点击立即检测；按并发上限排队并执行 |
| 调整账号或策略 | 检测期间也可保存软设置；当前采样继续，后续决策使用新策略 |
| 只改设置，不立即发请求 | 使用保存操作 |
| 停止当前检测 | 停止正在执行和排队的本轮请求；保留已有暂停与定时策略 |
| 排查管理端连接 | 在连接步骤检查或重新加载；错误留在对应位置 |
| 暂时不定时检测 | 关闭定时检测并保存；手动检测仍按明确操作发起 |
| 看细节 | 展开活动、采样记录和历史记录 |

页面自动读取运行时状态；关闭页面不等于停止后台巡检。状态过期、连接错误、插件未运行与正常空列表需要分别处理，不能把旧数据当作当前健康。

## 检测与恢复规则

- 默认同时巡检 3 个账号，可调 1–8。持续调度器在槽位空闲时立即处理到期目标，手动与定时任务共用并发上限；慢账号不会阻塞其他空闲槽位。
- 每轮需要 3 份独立有效样本。身份、端点、凭据、代理和请求头先校验，配置错误不消耗模型请求预算。400/401/403/404/422 等永久错误不重试；临时失败最多追加 2 次，采用指数退避与抖动并遵守 Retry-After，过长限流等待结束本轮。
- 采样失败显示“检测失败”；完整采样后仍无法可靠区分显示“判定不确定”，独立计数并展示候选。两者均不新增隔离，也不推进恢复确认。
- 开启自动暂停时，完整一轮确认参考结果不符后暂停新调度。
- 已勾选并保存启用管理的账号由插件统一管理调度。暂停账号连续两轮有效通过，且自动恢复开启后才恢复；`updated_at` 变化或外部 `schedulable=false` 不再锁死恢复。
- 自动暂停与自动恢复分别控制：关闭自动暂停后不会新增暂停；已启用管理的暂停账号（包括外部暂停）仍按自动恢复开关处理。
- 取消勾选并保存后，账号退出当前监测列表及隔离统计，已有记录收纳到“活动记录与诊断 → 未监测的历史记录”。停止后续巡检但不会解除已有暂停；重新勾选并保存后才会继续复测。
- 旧 `external_change` / `pause_uncertain` 记录不再永久阻断已启用管理目标，回到复测流程；不因升级立即恢复，不跳过连续两轮有效通过。
- 已删除账号不重建；不可见账号不猜测状态；账号状态非 `active` 或已过期时不改写宿主状态。需要停止插件管理某账号时，应取消勾选并保存，而非仅在宿主暂停调度。
- 正常检测默认 30 分钟；失败重试/恢复确认默认 2 分钟；隔离复测默认 6 小时。新增可选恢复确认间隔（默认 0，沿用现有节奏）和家族级匹配（默认关闭）；开启家族匹配会接受参考库同家族且预期位于前两名的完整评分，可能跨代或跨档。
- 启动或管理地址／密钥／状态目录变更后的保护期为 60 秒；软设置保存不重启引擎、不重新计时。手动检测可以明确排队，不必等待保护期。
- 每日请求预算按 UTC 日界重置，工作台显示实际下一次重置时间。

暂停只影响新调度，不中断已经运行的请求。采样消耗上游账号额度，不进入普通 API Key 用量账单。

## API Key 账号

原版宿主不提供 API Key 类型的出站凭据。需要巡检 API Key 账号时，安装可选的本机 Unix Socket 助手；不修改 Sub2API 主程序，也不开放 TCP 端口。

助手在读取前后核对管理员密钥对该账号的权限，再通过专用只读数据库角色获取账号现有地址、Key、模型映射和代理。运行进程使用非 root 身份，不需要 Docker Socket。独立 healthz 只检查桥接响应，账号授权与上游请求结果分别展示。

参见 [本机 API 桥接安装与排障](docs/API-BRIDGE.md)。安装包同时携带该说明和助手脚本。未安装时，OAuth 仍走原生身份接口，API 账号提示所需配置。

API 上游需要支持 `/v1/responses` SSE。聚合渠道的隔离对象是该渠道账号，无法单独识别渠道背后的供应商账号。API 账号默认请求 `gpt-6.1-sol`，预期指纹使用 Astra/Sol 类，可自行调整。

## 构建与验证

需要 Go 1.26.10、Node.js 22 或更新版本，以及 Python 3.10 或更新版本。Go 依赖已经 vendored。

```sh
npm ci
make test
make check-package
```

`make test` 包含 Go 竞态测试、go vet、UI 行为回归和 Python 桥接回归。CI 另运行固定版本的 staticcheck、govulncheck、ruff、元数据一致性检查和性能基准；Unix Socket 测试使用本机短临时目录，可在网络盘项目中运行。

`make check-package` 会：

1. 构建 Linux amd64、Linux arm64 和本机运行文件。
2. 启动真实插件进程，验证握手、配置、Health、诊断和版本一致性。
3. 分别生成默认无签名包和一次性测试发布者的签名包。
4. 检查两个包的清单 schema、版本、源码内容、所有哈希和真实签名状态，并验证篡改、缺失文件、额外文件、坏签名及无效显式密钥都会失败。
5. 删除临时测试包及测试签名种子。

直接生成可安装的当前版本包：

```sh
make package
make verify-package
```

结果位于 `dist/ModelGuard-<VERSION>.s2plugin` 和 `dist/SHA256SUMS`。没有密钥时不生成 signature.json，也不会自动创建私钥或误用遗留公钥。若确实需要签名，仍可显式使用 `make package SIGNING_KEY=/secure/path/publisher.key`；显式密钥错误会失败，不会静默降级。

推送 `v<VERSION>` 标签后，CI 会执行测试、构建、打包与完整性检查，再自动发布安装包和校验文件。该流程使用仓库内建 GITHUB_TOKEN，不需要额外签名 Secret。发布时核对标签与提交，已存在的同名资产必须内容一致，不会覆盖不同内容或移动旧标签。

不要上传私钥、管理密钥、桥接令牌或生产状态文件。

`VERSION` 决定运行程序的构建版本和默认安装包名。修改版本后运行 `python3 scripts/sync-metadata.py` 同步 README、npm 与嵌入式元数据；`--check` 可检查漂移。插件标识与兼容范围来自 `internal/metadata/plugin.json`，推荐模型与别名来自同目录 `defaults.json`。没有生成当前版本正式包时，对应正式归档测试明确跳过；旧包通过验签不代表新代码已经打包。

## 数据与控制边界

原始回答仅在内存参与评分；页面巡检记录和持久化状态不保存上游凭据或原始回答。管理员访问密钥用于用户明确配置的管理连接，不进入状态快照和诊断日志。

暂停与复测记录会持久化；历史更新时间仅用于诊断，不再作为已启用管理账号的永久恢复锁。插件不改写账号非 active / 过期状态，不重建已删除账号。调度读写并非原子条件更新，避免多个自动控制器同时管理同一账号。部署保留管理目标、自动恢复开关及采样预算；改变恢复间隔或家族级匹配需要在设置中明确启用。详见 [管理策略调整与上线边界](docs/MANAGED-RECOVERY-2026-11-01.md)。

## 状态、审计与预算持久化

暂停／恢复意图、归属、归档和配置应用写入独立 `audit.jsonl`，按大小／条数轮转，至少保留最近 2000 条审计事件。采样进度与最近 300 条采样活动保留在内存，不再触发完整状态重写。活动页默认显示审计，可切换显示采样。

`state.json` 使用紧凑 JSON 和原子提交，暂停／恢复等关键状态仍同步落盘。`state.json.prev` 保存上一版有效状态；主文件损坏时提供恢复位置，不会静默采用旧状态。请求预算使用 16 次一组的保守持久化预留：正常退出保存准确用量，异常断电最多多计 15 次未使用额度，避免重启后重复使用已消耗预算。每日额度仍按 UTC 日界重置。

Health 按修订号缓存状态与账号 JSON；进度变化只标记脏数据，读取时才构建快照。界面复用账号与监测记录行，保留输入焦点和未保存内容。
