# ModelGuard · 模型哨兵

Sub2API 的账号模型指纹巡检插件。按“连接管理端 → 选择账号 → 确认策略并开始”完成接入，之后在同一工作台查看队列、采样、结果、暂停归属和下一步。

当前工作版本：**0.3.0**。重构说明与验收记录见 [全链路重构记录](docs/REFACTOR_2026-10-30.md)。

**指纹表示参考库内的统计相似度，不是模型身份认证或智力证明。** 超时、拒答、流中断和不完整样本不算指纹不符。

## 开始使用

### 1. 安装并启用插件

从 [Releases](https://github.com/cyeinfpro/ModelGuard/releases) 选择已发布的 `.s2plugin` 和 `publisher-public-key.txt`。源码中的工作版本不表示对应版本已签发或上线。

在 Sub2API 配置中添加可信发布者，按宿主流程重载配置并上传插件：

```yaml
plugins:
  allow_unsigned: false
  trusted_publishers:
    cyeinfpro-account-guard-v1: "publisher-public-key.txt 中的公钥"
```

启用插件后打开配置页。插件进程是否启用，与插件内“定时检测”是否开启，是两个不同状态；关闭定时检测仍可以手动检测。

宿主契约按官方 Sub2API 0.2.19 对齐，兼容声明为 `>=0.2.19 <0.3.0`。插件参与 `openai.oauth.outbound_transport.v1` 绑定，部署时检查现有传输插件。默认状态目录为 `/app/data/sub2api-account-guard`。

为兼容已有安装，内部插件 ID 仍为 `local.sub2api.account-guard`，发布者 ID 和状态目录保持兼容。

### 2. 连接管理端

在接入第一步填写本站管理地址和管理员访问密钥，执行“保存连接并加载账号”。

管理地址使用站点根地址，例如 `http://127.0.0.1:8080`。非本机地址必须使用 HTTPS。密钥授权范围需要覆盖准备巡检的账号：

- 读取账号需要 `accounts.read`。
- 自动暂停与自动恢复还需要 `accounts.status`。

宿主 UI Bridge v1 的 `config.test` 只测试已保存配置，所以连接操作先保存，再检查与加载。连接成功表示能读取相应账号列表，不表示已经验证所有上游模型或调度写权限。插件不会通过暂停真实账号来测试写权限。

### 3. 选择账号与策略

勾选需要巡检的账号。常规使用采用账号推荐模型；需要指定渠道模型名或参考类时，再展开模型设置。

“请求模型”是发送给上游的名称；“预期指纹”是检测时对照的参考类。API 渠道可以对模型名做映射，这两个名称不一定相同。

确认定时检测、并发和自动处理行为后开始。工作台区分配置保存回执和后台检测接收状态，不把“已保存”当成“已检测”。

## 日常操作

| 想做什么 | 操作与结果 |
| --- | --- |
| 看当前情况 | 查看工作台中的账号、调度状态、采样阶段和下一步 |
| 手动检测一次 | 点击立即检测；按并发上限排队并执行 |
| 调整账号或策略 | 打开设置，编辑并保存；未保存内容不会因自动同步消失 |
| 只改设置，不立即发请求 | 使用保存操作 |
| 排查管理端连接 | 在连接步骤检查；错误留在对应位置 |
| 暂时不定时检测 | 关闭定时检测并保存；手动检测仍按明确操作发起 |
| 看细节 | 展开活动、采样记录和历史记录 |

页面自动读取运行时状态；关闭页面不等于停止后台巡检。状态过期、连接错误、插件未运行与正常空列表需要分别处理，不能把旧数据当作当前健康。

## 检测与恢复规则

- 默认同时巡检 3 个账号，可调 1–8；手动与定时任务共用并发上限。
- 每轮需要 3 份独立有效样本。失败样本最多追加 2 次重试。
- 检测失败保留调度状态，不新增隔离，之后按策略重试。
- 开启自动暂停时，完整一轮确认参考结果不符后暂停新调度。
- 恢复要求本插件持有暂停记录、连续两轮有效通过，且恢复前校验账号未被外部修改。
- 自动暂停与自动恢复分别控制：关闭自动暂停后不会新增暂停；已由本插件暂停的账号仍按自动恢复开关处理。
- 取消勾选会停止该账号的后续巡检，但不会解除已有暂停；重新勾选并保存后才会继续复测。
- 外部暂停只进行允许的观察/复测，不自动接管或恢复。
- 正常检测默认 30 分钟；失败重试/恢复确认默认 2 分钟；隔离复测默认 6 小时。
- 保存后的启动保护期为 60 秒；手动检测可以明确排队，不必等待保护期。
- 每日请求预算按 UTC 日界重置，工作台显示实际下一次重置时间。

暂停只影响新调度，不中断已经运行的请求。采样消耗上游账号额度，不进入普通 API Key 用量账单。

## API Key 账号

原版宿主不提供 API Key 类型的出站凭据。需要巡检 API Key 账号时，安装可选的本机 Unix Socket 助手；不修改 Sub2API 主程序，也不开放 TCP 端口。

助手在读取前后核对管理员密钥对该账号的权限，再只读获取账号现有地址、Key、模型映射和代理。桥接安装状态与真实请求是否成功分别展示；socket 文件存在不等于已经验证连通。

参见 [本机 API 桥接安装与排障](docs/API-BRIDGE.md)。签名包同时携带该说明和助手脚本。未安装时，OAuth 仍走原生身份接口，API 账号提示所需配置。

API 上游需要支持 `/v1/responses` SSE。聚合渠道的隔离对象是该渠道账号，无法单独识别渠道背后的供应商账号。API 账号默认请求 `gpt-6.1-sol`，预期指纹使用 Astra/Sol 类，可自行调整。

## 构建与验证

需要 Go 1.26.1、Node.js 22 或更新版本，以及 Python 3.10 或更新版本。Go 依赖已经 vendored。

```sh
npm ci
make test
make check-package
```

`make test` 包含 Go 竞态测试、go vet、UI 行为回归和 Python 桥接回归。

`make check-package` 会：

1. 构建 Linux amd64、Linux arm64 和本机运行文件。
2. 启动真实插件进程，验证握手、配置、Health、诊断和版本一致性。
3. 使用一次性测试发布者生成当前版本测试包。
4. 检查清单 schema、版本、文件内容、签名和所有哈希。
5. 删除测试包及测试签名种子；不生成正式发布包。

生产打包使用仓库外的既有 Ed25519 签名种子：

```sh
make package SIGNING_KEY=/secure/path/publisher.key
make verify-package
```

仅首次自建发布者需要创建密钥；后续版本必须继续使用同一把密钥。不要覆盖已有发布者，也不要上传私钥、管理密钥、桥接令牌或生产状态文件。

`VERSION` 决定运行程序的构建版本和默认安装包名。没有生成当前版本正式包时，对应正式归档测试明确跳过；旧包通过验签不代表新代码已经打包。

## 数据与控制边界

原始回答仅在内存参与评分；页面巡检记录和持久化状态不保存上游凭据或原始回答。管理员访问密钥用于用户明确配置的管理连接，不进入状态快照和诊断日志。

暂停归属记录会持久化。恢复前检查更新时间与状态，但宿主调度接口不支持原子条件更新，检查与写入之间仍有短暂竞态。不要让多个自动控制器同时管理同一账号。
